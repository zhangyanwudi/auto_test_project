# 巡检基建平台 Skill

## 🔒 上下文隔离机制

遵循后端通用的 `@` 指令上下文隔离规则：消息以 `@` 开头 → 仅发送 system prompt + 当前消息，不携带历史上下文。

## ⛔ 触发条件

**仅在用户消息以以下前缀开头时激活：**
- `@case-explore`、`@巡检基建平台`

**以下情况不要激活：**
- 普通对话中提到「巡检」「基建平台」但没有 `@` 前缀
- 任何不以 `@` 开头、或其它 `@` 命令

## 执行流程

1. 用户消息形如：`@巡检基建平台 巡检达人管理，验证批量上传后列表出现上传的达人`
2. 提取用户描述（去掉 `@` 命令前缀后的剩余文本）作为 `description`
3. 调用 `case_explore` 工具：

```
[TOOL_CALL:case_explore]{"description":"巡检达人管理，验证批量上传后列表出现上传的达人"}[/TOOL_CALL]
```

4. 工具会：
   - 默认从 `https://marketing-test.youxi123.com/` 首页开始巡检（用户无需提供 URL）
   - 生成「节点规范草稿」（precondition / step / result）
   - Playwright 无痕试运行
   - 返回每步执行结果

5. 把工具返回的结果格式化展示给用户（含规范草稿 + 每步通过/失败 + 提示「确认固化」）。

## 注意事项

- description 是「要巡检功能的自然语言描述」，无需带 URL；默认从基建平台首页开始
- 用户明确给出其它 URL 时，以用户给的 URL 为准
