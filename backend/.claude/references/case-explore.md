# 生成巡检规范 Skill

## 🔒 上下文隔离机制

遵循后端通用的 `@` 指令上下文隔离规则：消息以 `@` 开头 → 仅发送 system prompt + 当前消息，不携带历史上下文。

## ⛔ 触发条件

**仅在用户消息以以下前缀开头时激活：**
- `@case-explore`、`@生成巡检规范`、`@生成规范`

**以下情况不要激活：**
- 普通对话中提到「巡检」「规范」但没有 `@` 前缀
- 任何不以 `@` 开头、或其它 `@` 命令

## 执行流程

1. 用户消息形如：`@生成巡检规范 巡检 https://xxx 的线索库页面，验证列表加载和搜索功能`
2. 提取用户描述（去掉 `@` 命令前缀后的剩余文本）作为 `description`
3. 调用 `case_explore` 工具：

```
[TOOL_CALL:case_explore]{"description":"巡检 https://xxx 的线索库页面，验证列表加载和搜索功能"}[/TOOL_CALL]
```

4. 工具会：
   - 生成「节点规范草稿」（precondition / step / result）
   - Playwright 无痕试运行
   - 返回每步执行结果

5. 把工具返回的结果格式化展示给用户（含规范草稿 + 每步通过/失败 + 提示「确认固化」）。

## 注意事项

- description 必须包含页面 URL（或域名）和要验证的功能描述
- 用户没提供 URL 时，提示用户补充要巡检的页面地址
